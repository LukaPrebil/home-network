# Internet-expose Mattermost via Cloudflare with scoped at-rest encryption

Status: accepted (2026-06-30). Superseded by ADR 0010 (2026-08-08): the service was removed entirely.

We are self-hosting Mattermost (free Team Edition, local auth, capped at 20 users) as the team chat - a Slack replacement for a fully-remote 7-person dev/product team plus a GitHub bot. Mattermost stores message content as plaintext in Postgres and offers no end-to-end encryption (the server, and anyone with DB access, sees everything); search and compliance export depend on that plaintext. The only operator ever on the LAN is the homelab owner, so every human user reaches the service from off-LAN.

We decided to expose it publicly at `chat.lukapg.dev`, mirroring the existing PDS pattern: Cloudflare proxy (WAF + Bot Fight) -> Traefik (CrowdSec IDS + global rate limit + TLS via Let's Encrypt) -> app, with Mattermost's own local auth as the inner layer and open registration disabled (invite-link onboarding only). Internal-only + Tailscale was rejected because it would lock out the entire remote team and break the GitHub plugin, which needs GitHub's servers to reach the Mattermost webhook/OAuth endpoints inbound.

Because the message store is plaintext and the existing `truenas-vms` ZFS dataset is unencrypted - and ZFS cannot encrypt a dataset in place without migrating every guest's disk image - we provision two NEW encrypted TrueNAS datasets rather than touching the shared one: an NFS-backed dataset exposed as a Proxmox storage that holds the `mattermost` LXC's rootfs (OS + Docker + Postgres, all encrypted; Postgres stays on local rootfs per the no-DB-on-NFS convention, just on encrypted storage), and a separate encrypted NFS dataset for file uploads. Both use ZFS keyfile auto-unlock (not a manual passphrase) so the service recovers unattended after a power event - acceptable because the accepted threat model is a stolen or decommissioned disk, which a key on the TrueNAS boot pool still defends against. The recovery key is exported once and stored offline.

Consequences: the enforced perimeter for this service is the WAN edge (Cloudflare -> Traefik -> CrowdSec) plus Mattermost local auth; the flat-LAN trust-boundary exposures deferred in ADR 0001 are unchanged by this. At-rest encryption protects only against physical disk theft - it does NOT hide content from the operator, a live-host compromise, or theft of the whole running server (the key lives on the box). Free Team Edition limits are accepted deliberately: best-effort mobile push via TPNS (HPNS is paid), 1:1 calls + screen share only with group video deferred to external Meet/Zoom, and no SSO/SAML. ZFS snapshots and replication of the two datasets inherit the encryption, so backups are covered for free.
